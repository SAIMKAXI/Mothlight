# Android preview signing

Mothlight preview APKs use a persistent **test-only** Android signing key. This allows later preview builds to update an installed preview build without Android rejecting it because the signing certificate changed.

Do not commit the keystore or its passwords. Keep a secure offline backup of the keystore: losing it means future APKs cannot update the currently installed app.

## Create the keystore on Windows

Run this in PowerShell from a private folder on your computer:

```powershell
keytool -genkeypair -v -storetype JKS -keystore mothlight-test.keystore -alias mothlight-test -keyalg RSA -keysize 2048 -validity 10000
$base64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD/mothlight-test.keystore"))
Set-Clipboard $base64
```

Choose a strong keystore password and key password when prompted. Keep both safe. The alias in this example is `mothlight-test`.

## Add GitHub Actions secrets

In the repository, open **Settings → Secrets and variables → Actions → New repository secret** and add:

| Secret name | Value |
| --- | --- |
| `MOTHLIGHT_TEST_KEYSTORE_BASE64` | The Base64 value copied to your clipboard |
| `MOTHLIGHT_TEST_KEYSTORE_PASSWORD` | The keystore password you chose |
| `MOTHLIGHT_TEST_KEY_ALIAS` | `mothlight-test` |
| `MOTHLIGHT_TEST_KEY_PASSWORD` | The key password you chose |

The Android release workflow checks that all four secrets exist, restores the keystore on the runner, and configures the release variant to use the persistent signing configuration. Never paste the passwords or Base64 keystore into a commit, issue, or public chat.

## One-time transition from v0.2.7

The v0.2.7 APK was signed with a temporary key generated by its GitHub Actions runner. That private key is not available for future builds, so Android cannot accept a stable-signed v0.2.8 APK as an in-place update over v0.2.7.

Before removing the old preview, save any notes you need using the app's Share note action. **Uninstalling the old preview clears its local app data.** Install the first stable-signed build only after backing up important notes. After that one-time transition, subsequent builds signed with this same keystore can update normally.

This key is for tester sideloads only. Do not use it for Google Play or production distribution.
